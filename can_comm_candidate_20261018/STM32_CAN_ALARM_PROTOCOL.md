# CS500 → STM32 CAN 故障报警协议

## 用途与边界

- 电机启停、运行占空比、锁存停机、清故障、AI 和采集操作都走电脑到 CS500 的 SSH/以太网控制链路。
- CS500 的 CAN0 只向 STM32 发布故障报警；STM32 收到报警后控制蜂鸣器。
- CAN 上行只接收 STM32 的报警确认帧。电机控制类 CAN 帧一律忽略。
- STM32 每次复位先通过 `0x190` / `0x191` 配对，配对成功前忽略报警帧。
  详细格式见 [PAIRING_PROTOCOL_CN.md](PAIRING_PROTOCOL_CN.md)。

## 总线设置

- 经典 CAN，500 kbit/s。
- 11 位标准帧，DLC=8，数据字段采用小端序。
- CS500 J11：1 脚 GND、2 脚 CANL、3 脚 CANH。STM32 必须接 CAN 收发器，不能把 MCU 的 CAN_TX/RX 直接接到 CANH/CANL；CANH、CANL 对接并共地。仅在总线两端各保留一个 120 Ω 终端。

## CS500 故障报警帧

| 项目 | 值 |
|---|---|
| CAN ID | `0x180` |
| 帧类型 | 标准数据帧 |
| DLC | 8 |
| 数据 | `seq:u32`, `fault:u8`, `flags:u8`, `milliseconds:u16` |
| 字节序 | 小端 |

数据布局：

| 字节 | 含义 |
|---|---|
| 0–3 | 单调递增的事件序号 `seq` |
| 4 | 故障码 |
| 5 | 时间有效标记等标志位；蜂鸣器逻辑可忽略 |
| 6–7 | 毫秒字段；蜂鸣器逻辑可忽略 |

故障码：`1 PL_MOTOR_FAULT`、`2 ADC_ERROR`、`3 DMA_DROP`、`4 TIMESTAMP_MISMATCH`、`5 SEQ_GAP`、`6 CURRENT_LIMIT`、`7 VIBRATION_LIMIT`、`8 MANUAL`、`255 OTHER_EVENT`。

CS500 对未确认报警约每 2 秒重发。STM32 应以 `seq` 去重：新序号触发一次蜂鸣器提示，重复序号只重发确认、不重复鸣叫。

## STM32 报警确认帧

| 项目 | 值 |
|---|---|
| CAN ID | `0x280` |
| 帧类型 | 标准数据帧 |
| DLC | 8 |
| 数据 | `seq:u32`, `mask:u8`, `receiver:u8`, `reserved:u16` |
| 字节序 | 小端 |

对刚收到的报警回复：`seq` 填报警序号，`mask=0x01`，`receiver=0x01`，`reserved=0`。即 8 字节布局为 `seq[0] seq[1] seq[2] seq[3] 01 01 00 00`。收到确认后 CS500 停止重发该序号。

建议 STM32 先把报警放入本地待处理状态并启动蜂鸣器，再发送确认。确认帧只表示 STM32 已接收报警，不表示故障已经消除。

## 联调顺序

1. 配置 STM32 CAN 外设为 500 kbit/s，接收过滤器匹配标准 ID `0x180`。
2. 收到 `0x180` 后校验 DLC=8，解析故障码；新 `seq` 蜂鸣一次，重复 `seq` 不重复鸣叫。
3. STM32 按上述格式回发 `0x280`。
4. 先用故障注入或断开 VM 的条件验证报警和确认重发，再验证电脑通过 SSH/以太网查询状态和执行控制。

当前工作区没有 STM32 工程，因此这里只定义双方可实现的线上协议；STM32 外设初始化与蜂鸣器驱动需按实际 MCU 型号接入。
